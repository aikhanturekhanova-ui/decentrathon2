## Merge with the fourth review (2026-10-31) and the Gemini provider
* The team's «Fourth review» (account takeover wordings, Green Zone facts, LLM whitelist and hard deadline) was fast-forwarded into this working
  copy; all code merged without conflicts (only generated metrics and one trace row conflicted, resolved by regeneration / by hand).
  Merged: 741 tests pass; safety audit on 119,337 real tickets + 3,000 fuzz: no violations; VALID silver agreement 0.842 → 0.897.
* Found and fixed while merging: (1) the toxicity type names were shadowed by classify's INSULT/PROFANITY regexes, so quoted plain insults
  never added insult evidence (pyflakes); (2) the reference template given to the LLM contained «Что говорят правила:», which the guard forbids
  the model to write, so most real drafts were rejected; (3) the template's own safe sentences failed the model-text checks: verbatim template
  sentences are now trusted, the model's own sentences are checked as before (acceptance 13.9 % → 60.7 %); (4) Gemini 3 rejects
  `thinkingBudget: 0` with a bare INVALID_ARGUMENT (now `thinkingLevel: minimal`, and such a 400 is retried once without the field);
  (5) a local `.env` key would have sent REAL tickets to a free LLM tier from the evaluation scripts: `LLM_ENABLED=0` is now forced there;
  (6) a stray «привет» line at the end of README; (7) the Docker image lacked `docs/metrics` (dashboard history); (8) «2 жалоб(ы) от 1 других
  автора(ов)» grammar; (9) unused imports/variables (pyflakes clean); (10) a missing model is now a loud warning in `make predict` and in its stats.

## Audit findings

### Fixed in this pass
1. **Classifier systematically mislabelled appeals.** A punished player writing about the violation they were punished for («я не использовал софт», «не дмил») was classified by the violation word (cheat/dm) instead of `complaint.admin`. The learned model fixes most of these (largest error class of the lexicon on the TRAIN hold-out).
2. **Silver labels ignored metagaming/NonRP/PG.** `silver_category` mapped only DM/DB/TK/SK; admin decisions recorded as «MG», «MetaGaming», «NonRP» were unlabelled. Fixed in `scripts/_common.py` (affects all silver metrics).
3. **Blend could never pick a category unknown to the model** (found by a new test). Fixed: the blend runs over the union of classes.
4. **Mobile layout** of the admin panel overflowed to 800 px on a 390 px screen; «Экспорт правок» was blue-on-dark in dark mode. Fixed.
5. Requirements trace claimed Linux/`make` were unverified: now run (tests, `make predict`, `make train`, server + UI).

### Verified working (not changed)
Contract and schema validation, adapter (admin text is dropped before processing), safety flags and priority raises, RAG anchor/context checks, guard, SQLite queue,
edit export, template suggestions, demo seed, CLI robustness (BOM, broken lines).

### Not changed, worth knowing (see the final summary for the full list)
* The admin API has **no authentication** (fine for a local demo, not for deployment).
* Drafts are formulaic templates; the LLM mode was run once against Gemini (free tier, artificial tickets, cost unknown) before the fifth review tightened the guard, so that acceptance rate does not describe the current code.
* Hidden-test accuracy remains unknown: there are no human labels.

## Evaluation protocol of the new model (no leakage)
TRAIN only for fitting; 20 % of reporters held out (grouped by `reporter_hash`, so no author is on both sides) to choose the blend weight; VALID used only to confirm.
VALID labels (category/priority) do not exist; its verdict fields are used only to derive silver labels for scoring, never for training.
The TRAIN sample in `docs/metrics/silver.json` is in-sample for the model and is marked as such.
