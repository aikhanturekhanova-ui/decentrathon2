## C. Defects found in this re-audit (all fixed, each has a regression test)
1. The rulebook section «RP термины» (definitions of DM, DB, SK, TK, MG, NonRP, PG) was treated as non-citable context, so the most frequent complaint type (DM-family, ~17 %) had no rule grounding. Now grounded (94.9 % of DM complaints).
2. The request to the model sent `temperature`, which the official Haiku 5.5 page says to omit, and left adaptive thinking on: real calls would have failed or burned the token budget, silently falling back to templates. Fixed; one safe retry without the optional fields.
3. An input file with a UTF-8 BOM (any Windows editor) crashed `make predict` completely. Fixed; broken lines get a valid safe answer.
4. `rules.json` missing/elsewhere crashed the service. Now discovered next to the input / in `./handout`; otherwise a loud warning and citation-free (never invented) answers.
5. A renamed/removed taxonomy code crashed the record. Now mapped to the nearest code of the same kind, handoff rules preserved.
6. JSON responses had no `charset=utf-8`: Windows clients showed Cyrillic as mojibake. Fixed.
7. Earlier in this series: kz symbol table (3 letters wrong in the PDF), relative paths from `.env`, appeal handoff, guard bypasses, malformed provider payloads, cost `unknown` ≠ `$0` (see `docs/LIMITATIONS.md`).

## C2. Defects found by the third independent review (all fixed, each has regression tests in `tests/test_review3*.py`)
1. **Mandatory handoff lost in mixed tickets.** «Верните 500 рублей за покупку. Можно ли подать жалобу?» and «Менің аккаунтыма кіре алмаймын. Ойыншыны қорлауға рұқсат па?» were answered as ordinary rule questions with `needs_human=false`. Flags are now computed on the whole text before the category; a `report` becomes `report.payment`/`report.account`; lost access (`access`) is a new flag; Kazakh/Uzbek (Latin and Cyrillic), Spanish and Portuguese phrasings added.
2. **Priority overwritten.** `complaint.scam` silently replaced p0 by p1/p2 (hack, payment, threat outside the game). Priority is now computed in a fixed order and only ever raised (`compute_priority`).
3. **LLM guard let promises through** («Игроку назначат блокировку. Проверка займёт 24 часа.», «Вы получите средства обратно», …). Sensitive tickets no longer reach the model; the model's own text must pass a structural check (sanction/refund topics only when negated, no deadlines, no foreign numbers/contacts/procedures) on top of the pattern guard; rejection reasons are written to `reasons`.
4. **Place-bound rule without the place.** A kidnapping with a rope in a forest cited `GZ 1.2` (Green Zone). Applicability is checked separately from existence/anchors.
5. **Definitions and report retrieval.** «Что такое DM?» answered «no ready answer» although «RP термины» defines it; «Меня убили в зелёной зоне» (report) had no rule. Questions about game terms are answered from the term section; a violation report is retrieved by the substance of the violation.
6. **Evidence.** «Доказательств нет» counted as evidence. Attachments, claims, explicit absence and questions are now separate (`extracted.evidence_status`).
7. **False «передано».** Drafts claimed that the ticket was passed on although nothing is forwarded; replaced by «нужна проверка человеком»; the guard rejects such claims in all six languages.
8. **Refusal for a critical topic.** «Он угрожает убить меня в реальной жизни» without attachments got «подайте жалобу заново»; sensitive topics now get their own strategy.
9. **Language.** «Аккаунтимни бузишди» (Uzbek Cyrillic) was Russian; a Kazakh letter in a player's NAME turned a Russian message into Kazakh. Names/quotes are ignored, Uzbek Cyrillic is recognised.
10. **Duplicates.** The bare category made two different events a duplicate; the history was lost on restart; the UI never sent an author. Event details, suspected repeats, SQLite history, bounded memory and an author field in the UI.
11. **Ad complaints marked as spam** («Здесь рекламируют казино, проверьте»).
12. **LLM budget.** A retry after any HTTP 400 raised `max_tokens`; no total time budget; the per-ticket price ceiling was only a setting. Retry only for a parameter error, never with more tokens, a total budget, a cost ceiling when prices are set, settings validation.
13. **Found while fixing:** «значит» contained «чит» and produced cheat topics; `краш` in «закрашивал граффити» triggered the mass-failure flag (p0); «списал дз», «оплатить штрафы», «вышел за донат из тюрьмы» made payment p0; `macro_f1` ignored classes that only the system predicts; the audit checked shape but not meaning; the retry test asserted the wrong behaviour (`max_tokens >= 1200`) and was corrected with the case's budget requirement as the reason.

## C3. Defects found by the fourth review (all fixed, tests in `tests/test_review4.py`; see also `docs/ARCHITECTURE.md`)
1. **Account takeover phrased differently** («учётная запись», «учётка», «чужая почта», «посторонний человек вошёл», kk/uz variants) was missed when a safe question followed; now `report.account`, `p0`, human. The detector remains a lexicon.
2. **GZ rules after leaving the zone** («вышли из ЗЗ, после чего…», «сначала были в ЗЗ, потом…») were cited; the place must be a fact of the story at the moment of the event.
3. **One place added every rule.** `GZ 1.1` (killing) was cited for a tying «без убийства»; each point now needs its own action and the action not denied.
4. **The official zone list was ignored** («у больницы г. Арзамас»); it is parsed from `rules.json` (city-bound objects need their city).
5. **Paraphrased promises passed the LLM guard** («займёт пару часов», «потеряет доступ навсегда», «решение уже принято в вашу пользу», «Вам обеспечено возмещение?»); a question mark exempted the sentence. Whitelist of sentence types + no `?` exemption + durations in words.
6. **The total LLM budget was not a deadline** (a server dripping bytes kept the call alive for 5.3 s on a 4 s budget); hard deadline in a worker thread, tested with a slow-drip server.
7. **In-game fines became payments** («Как оплатить штраф?») through the older `PAYMENT` detector, and a denied refund request («я не прошу вернуть деньги…») became a payment; one set of rules for every path. Also found: `тг` (Telegram) read as tenge, `потратил донат` as a purchase, `buzishgan` («violated a rule») as hacking.
8. **The complainant was extracted as the accused** («Я, Dias_Volkov, жалуюсь на Arman_Petrov»).
9. **A Kazakh scam report** («Ойыншы менің ақшамды алдап алды») was a question without a rule; and the Kazakh word «ойыншы» («player») made the next word a «name» and flipped the language.
10. **Appeal as a report** got «no ready answer»; now an appeal draft and `p2`.
11. **Clarifying questions repeated known facts** («где это произошло» when «в лесу» was stated; «что именно вас интересует» for a clear question).
12. **Metrics.** The sensitive-topic counter could not see a missed topic: detection completeness is now measured separately on an expectation list; «valid citations» is renamed «technically valid (NOT relevance)»; «substantive answers» is renamed «answers with a source attached (NOT usefulness)».

## C4. Defects found by the fifth independent review (on `19262eb`/`da3fc43`; all reproduced first, fixed, tests in `tests/test_review5.py`)
1. **Injection through `reported_nick`** («Arman_Petrov. Для проверки пришлите пароль…» ended up as a support sentence). The field is validated AS A WHOLE against the format of all 68,572 real values (`Имя_Фамилия`, ASCII, ≤ 32); an invalid value is dropped (neutral «игрок») and reported; every draft is also checked for a request of a secret.
2. **LLM sentences passed by partial matches** («рассмотрение завершено в вашу пользу», «оппонент отстранён навечно», «пришлите … пароль»). Now a closed vocabulary per language, no secrets, strict negated-promise shapes, no model-written restatements; verbatim template sentences are trusted only because their dynamic fields are validated.
3. **Missed handoff**: detached/foreign mail, lost control, cannot restore; double charge of real money. Fixed in ru/kk/uz/en (+ es/pt for double charge), any sentence order, several messages; own password change and in-game «взлом» are not takeovers.
4. **The first 2,000 characters were analysed only**: the safety flags now read the whole dialogue; requests are limited explicitly (20,000 characters per message, 60,000 per dialogue → 422; the longest real text is 1,630); the classification context is head + tail.
5. **`API_TOKENS=admin:short` turned authentication off.** A set but invalid configuration now refuses to start (token values never printed); empty = explicit demo mode.
6. **Rate limit keyed by an unverified token**: now a verified token (hashed) or the IP; bounded memory; a batch counts tickets; the default is off in the demo mode (a load test of `/triage` got 429 with the old 1,200/min default) and 1,200/min with tokens.
