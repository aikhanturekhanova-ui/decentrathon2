# Presentation outline and defence text (RU)

1. **Проблема (30 с).** 500 тыс. игроков, ответы однотипные, серьёзные случаи тонут. Ошибка ассистента дорогая: выдуманный пункт или обещанный бан.
2. **Что построили (45 с).** Сервис триажа: язык → категория/приоритет → извлечение фактов → правила из базы → черновик на языке игрока → «нужен ли человек и почему». POST /triage, `make predict`, панель админа, (опц.) LLM и Telegram.
3. **Главный принцип — нельзя выдумать.** Цитата допускается, только если пункт (а) существует с учётом раздела — номера повторяются в 57 случаях; (б) подходит по смыслу — проверка опорных слов в реальном тексте пункта; (в) не взят «на веру» у игрока. Поиск по словам сам по себе не даёт права цитировать: мы это измерили, он процитировал лишнее.
4. **Честность по ТЗ.** Пример из ТЗ обещает мут и «видно по скриншотам». У нас только число вложений, поэтому текст говорит «мы их не просматриваем», слова игрока — «по вашим словам». Тесты это проверяют на 6 языках.
5. **Данные и ML.** Разметки категорий нет, но в 29,5 тыс. жалоб train админ указал пункт правил или вердикт апелляции — это слабые метки. На них обучена модель (TF-IDF символьных n-грамм + логистическая регрессия), её вероятности смешаны со словарём: согласие со слабыми метками на valid 0,84 → 0,90, на отложенных авторах train 0,86 → 0,92. Главное исправление — апелляции наказанного игрока больше не путаются с нарушением, о котором он пишет. Безопасность, приоритет, передача человеку остаются правилами. Это не точность на скрытом тесте; ручная разметка подготовлена (`make review-set`).
6. **Безопасность.** Платежи, возвраты, взломы, потеря доступа, угрозы вне игры и апелляции — всегда человеку и p0 (кроме апелляции), даже если спрятаны в смешанном обращении или нет вложений; инъекции — это данные; сбой/мусор/обещание от модели → проверенный шаблон, причина пишется в `reasons`; чувствительные обращения к модели вообще не попадают. Черновик не говорит «передано»: он говорит «нужна проверка человеком». Это ограничения и проверки, а не гарантия: список шаблонов конечен, поэтому каждый черновик всё равно проходит через человека. Текст админа из датасета в конвейер не попадает.
7. **Цифры (из REPORT.md).** задержка в режиме шаблонов — единицы–десятки миллисекунд (точные p50/p95 в REPORT.md; задержка LLM-режима измерена один раз на искусственных обращениях с бесплатным Gemini до ужесточения проверок, для текущего кода не измерена); стоимость 0 $ в режиме шаблонов (LLM-режим: проекция ≈ 0,0003 $/обращение, реальная стоимость неизвестна); needs_human ≈ 86–93 % — осознанно.
8. **Чего нет (прямо).** Нет оценки носителей kk/uz; нет точности на размеченных данных; LLM проверен на заглушке.
9. **Дальше.** Разметка 300 тикетов двумя людьми; ревью kk/uz носителями; подключить ключ и измерить стоимость/задержку; кластеризация правок админов в шаблоны (в SQLite уже копятся правки).

**Вопросы жюри и ответы:** «Почему не LLM-классификатор?» — нет разметки и эталона, правила объяснимы и позволяют проверять жёсткие ограничения отдельно; LLM (если включён) пишет текст обычных обращений, а не решает. «Как убедиться, что цитаты настоящие?» — `tests/test_safety.py`, `tests/test_text_store_real.py` (реальный rules.json), guard на каждом ответе. «Почему 90 % — человек?» — каждое решение о наказании принимает админ; экономия идёт за счёт готового проверенного черновика.
